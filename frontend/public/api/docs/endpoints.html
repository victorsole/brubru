Brubru EU Data API · v2 · 1,065 endpoints across 96 EU institution folders

All endpoints

The complete Brubru EU Data API surface, organised one folder per EU institution or body. Every endpoint below is on the v2 API and authenticated with a single API key. This list is hand-grouped for browsing; the live API reference renders the same endpoints directly from the OpenAPI spec, so it is always exactly in sync with what is deployed.

One key, one envelope. Every call takes the same Authorization: Bearer brubru_live_... header and every list endpoint returns the same paginated response envelope. Detail endpoints (paths ending in an id, CELEX, reference or slug) return a single object. Base URL: https://brubru-production.up.railway.app/api/v2.

Funding, grants & tenders 161 endpoints

One standard across the funding lists. Every item carries the canonical datapoints: id, self, public_url, body_txt, body_html, document_date (the publication date at the source, or null; never a deadline or an opening date), creation_date (when Brubru first saw the item) and updated_date (the last real change of its content), plus item_type, title, summary, status, body_code, body_name and amount_eur.

The lists take q, page, limit (default 50, up to 200), include_body (on by default), updated_from/updated_to, published_from/published_to, created_from/created_to and order. A parameter a list does not know is named in ignored_parameters, so a filter that did nothing never reads as one that worked.

Start from the consolidated lists: /funding/opportunities (every call and tender, each procedure once, copies in same_as), /funding/awards (funded projects, funding recipients and contract awards), /funding/budgets (the money by fund) and /funding/partners (organisations and what they have done). The other lists are views of the same items. Routes marked deprecated keep answering for at least 12 months.
